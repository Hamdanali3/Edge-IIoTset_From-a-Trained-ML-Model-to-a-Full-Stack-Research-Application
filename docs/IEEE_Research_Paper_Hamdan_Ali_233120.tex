\begin{abstract}
Intrusion detection models evaluated on Edge-IIoTset routinely report accuracy above 99\%, yet the benchmark contains build artifacts that a classifier can exploit without learning anything about network behavior. We audit the 157,800-row machine learning release and document four problems: placeholder zeros serialized inconsistently as \zero{} and \zerof{} across the capture files from which the table was assembled, a comma fault in TShark exports that pushes text into a numeric column, eight constant fields, and 5,414 duplicate rows. We then remove the fifteen columns that identify the laboratory network, including addresses, timestamps, and raw payload strings. That step discards most of the evidence for web attacks, so before deleting the columns we convert them into 24 scalar descriptors of port roles, TCP options, payload entropy, and request structure. We call this representation privacy-preserving protocol-header structural feature engineering (PP-PSFE). On a stratified split of 152,386 flows, XGBoost trained on the resulting 62 features reaches 96.49\% accuracy and 0.9618 macro-F1, ahead of logistic regression (84.87\%) and random forest (94.38\%) and level with LightGBM (96.33\%), with a smaller train--test gap and 3.54~ms inference time per 1,000 flows. The five hardest HTTP-facing classes reach F1 between 0.86 and 0.93, against 0.44 and 0.66 for the linear baseline. We state plainly what this evidence does not establish, and we package the model as a REST service with a browser front end.
\end{abstract}

\section{Introduction}
\IEEEPARstart{I}{ndustrial} networks used to be quiet places. A programmable logic controller talked to a few known peers over Modbus, and an air gap separated the plant floor from everything else. Much of that separation is gone. Sensors publish to MQTT brokers, edge gateways expose HTTP interfaces, and engineering workstations sit one routing hop from corporate IT~\cite{sisinni2018,zolanvari2019}. The attack surface grew with the connectivity, and intrusion detection systems (IDS) that learn from labeled traffic have become a common response.

Edge-IIoTset~\cite{ferrag2022,ferragdata} was built to support that work. It was captured on a multi-layer testbed with more than ten kinds of IoT and IIoT devices, and it labels benign traffic together with fourteen attack types. The machine learning release, \texttt{ML-EdgeIIoT-dataset.csv}, holds 157,800 rows and 63 columns. In the original study, 15-class accuracy ranged from 67.11\% for a decision tree to 94.67\% for a deep neural network~\cite{ferrag2022}. Later papers report far higher figures, and the results are described as clustering above 99\%~\cite{galal2026}.

Two things bothered us about that gap. A jump of five points or more from changing the classifier is unusual on a 15-class problem with heterogeneous protocols. And the wider network-IDS literature has repeatedly warned that benchmark accuracy says little about deployment, because datasets carry artifacts that models learn instead of attacks~\cite{sommer2010,arp2022,engelen2021,liu2022,flood2024,kostas2025}.

We came to the dataset to build a classifier, not to audit it. Loading the file with pandas raised a \texttt{DtypeWarning} on nine columns, and following that warning led to most of what this paper reports. The same zero appears as the string \zero{} in some capture files and as \zerof{} in others, so a categorical encoder sees two categories where the network sees one absent field. Because normal and attack traffic were exported separately, the token tells a model which file a row came from. Galal~\cite{galal2026} has described this artifact, and we cite that work as the primary reference for it. We reproduce the artifact on our own copy and add per-class counts for several fields, a second export fault, and an analysis of what remains after cleaning.

Cleaning has a cost. The columns that carry lab identity, namely addresses, timestamps, raw ports, and raw payload strings, also carry the content of web attacks. Deleting them leaves 38 protocol fields that say little about the difference between a SQL injection, a cross-site scripting probe, a file upload, a password guess, and an HTTP flood. Our response is to extract compact structural summaries from the dropped columns first, and to discard the originals afterwards.

This paper makes four contributions.
\begin{enumerate}
\item \textbf{A reproducible audit and sanitization procedure} for the ML release of Edge-IIoTset. It canonicalizes placeholder tokens, repairs a TShark column shift, removes eight constant fields and fifteen identifier or raw-string columns, and removes 5,414 duplicate rows (157,800 to 152,386 flows) before any split.
\item \textbf{PP-PSFE}, 24 scalar features computed from the columns that the sanitization step removes. They describe port roles, TCP option and payload structure, payload entropy, and application-layer lengths and lexical markers.
\item \textbf{A four-model benchmark} (logistic regression, random forest, LightGBM, XGBoost) with per-class results and TreeSHAP attributions on a stratified split in which every encoder and scaler is fitted on training data only.
\item \textbf{A deployable artifact}: the fitted preprocessing and model are bundled into one scikit-learn pipeline behind a Flask service and an Angular interface, with continuous integration.
\end{enumerate}
We also give a frank account of what the experiments cannot show (Section~\ref{sec:limits}), complemented by a systematic feature-group ablation and a time-ordered evaluation that isolate the contribution of PP-PSFE and test temporal stability across capture periods.

The rest of the paper is organized as follows. Section~\ref{sec:related} reviews related work, Section~\ref{sec:audit} presents the audit, Section~\ref{sec:method} describes sanitization and PP-PSFE, Section~\ref{sec:setup} gives the experimental setup, Sections~\ref{sec:results} and~\ref{sec:xai} report results and explanations, Section~\ref{sec:deploy} describes the service, and Sections~\ref{sec:limits} and~\ref{sec:conclusion} discuss limits and conclude.


\section{Related Work}\label{sec:related}
\textbf{Edge-IIoTset and reported accuracy.} Ferrag \emph{et al.}~\cite{ferrag2022} released the dataset with centralized and federated baselines. Tareq \emph{et al.}~\cite{tareq2022} analyzed it with deep models alongside two other IoT benchmarks. Since then it has become one of the standard testbeds for IIoT intrusion detection, and the headline accuracy figures have moved close to 100\%.

\textbf{Evaluation pitfalls in network IDS.} Sommer and Paxson argued that anomaly and classification-based detection faces problems that do not arise in other machine learning applications~\cite{sommer2010}, and Arp \emph{et al.} catalogued recurring mistakes in security papers, including sampling bias and data snooping~\cite{arp2022}. Kapoor and Narayanan show how leakage undermines reproducibility across machine-learning-based science more generally~\cite{kapoor2023}. For network datasets in particular, Engelen \emph{et al.} and Liu \emph{et al.} documented construction and labeling errors in CIC-IDS-2017 and CSE-CIC-IDS-2018~\cite{engelen2021,liu2022}. Flood \emph{et al.} studied seven benchmark datasets and named six recurring design smells, among them features of outsized importance that have little to do with the attack mechanism~\cite{flood2024}. Kostas \emph{et al.} found that models built on individual packet features can reach near-perfect detection rates that fall by more than 90\% in cross-session tests~\cite{kostas2025}. Roy examines shortcut learning and flow-level versus capture-disjoint splitting in IoT IDS evaluation~\cite{roy2026}.

\textbf{The serialization artifact.} Galal~\cite{galal2026} shows that the standard preprocessing recipe for Edge-IIoTset turns a placeholder serialized differently in two branches of the dataset build into a near-perfect label proxy, and that file provenance becomes the label. That work goes on to rebuild a benchmark from raw captures. Our paper starts from the same observation on the same file but asks a different question: once the artifact and the identifying columns are gone, how much of the 15-class structure can be recovered from what the file still contains, and which of the recovered features can be trusted?

\textbf{Models.} We compare a linear baseline with three tree ensembles: random forest~\cite{breiman2001}, LightGBM~\cite{ke2017}, and XGBoost~\cite{chen2016}. Tree ensembles are a sensible choice for tabular data with mixed scales and many binary indicators~\cite{grinsztajn2022}, and they admit exact TreeSHAP attributions~\cite{lundberg2020}.

The direction of the token split depends on the column. In the four MQTT and DNS fields the benign class carries \zero{}, while in \feat{http.request.method} the volumetric classes carry \zerof{} and the web classes carry \zero{}. This is what one would expect if the table was assembled from separately exported capture files, each typed by its own content, though the file's history is not documented and we cannot confirm it.

We did not try to measure how much each problem inflates a model that is allowed to see it. Galal~\cite{galal2026} does that with cross-validated measures. Our interest is in what a model can still learn after the problems are removed.

\section{Method}\label{sec:method}
\subsection{Canonical sanitization}
Let $v$ be a raw cell. For every categorical protocol field we apply
\begin{equation}
S(v)=\begin{cases}\texttt{"0"} & \text{if } \operatorname{trim}(v)\in\{\texttt{"0"},\texttt{"0.0"},\texttt{"0.00"}\},\\ \operatorname{trim}(v) & \text{otherwise,}\end{cases}
\label{eq:canon}
\end{equation}
so that one absent field has exactly one representation. For \feat{dns.qry.name.len} we convert to a number and, where conversion fails because of the column shift, fall back to the character length of the offending string. We then drop the eight constant fields, the fifteen identifier and raw-string columns (after PP-PSFE extraction), and the second label column.

\subsection{PP-PSFE features}
The premise is that a raw column mixes two things. One is topology-specific identity: addresses, times, random client ports, full URLs. The other is protocol structure: which role a port plays, how long a payload is, whether a TCP option is present, how random a byte sequence looks. The first must go. The second is what separates a flood from a login attempt. PP-PSFE keeps only scalar summaries of the second kind. We use ``privacy-preserving'' in a narrow sense: no address, hostname, timestamp, URL, or payload content survives in the final feature vector. We do not claim that the features carry no information about the testbed (Section~\ref{sec:limits}).

\textbf{Group A: port roles (9 features).} Let $p_s$ and $p_d$ be the TCP source and destination ports; for non-TCP packets both are zero. We project them onto direction-invariant coordinates,
\begin{align}
p_{\text{service}} &= \begin{cases}\min(p_s,p_d) & \text{if } \min(p_s,p_d)<10^4,\\ 0 & \text{otherwise,}\end{cases}\label{eq:service}\\
p_{\text{eph}} &= \max(p_s,p_d),\qquad \Delta p=|p_s-p_d|,\label{eq:eph}\\
d &= \operatorname{sgn}(p_s-p_d),\label{eq:dir}
\end{align}
and add five binary indicators: either port in $\{80,443,8080\}$ (\feat{psfe_is_http_service}); either port equal to 1883 (\feat{psfe_is_mqtt_service}); either port in $\{4321,3333,5900\}$ (\feat{psfe_is_iot_c2_service}); either port equal to 65535 (\feat{psfe_is_boundary_probe}); and a nonzero UDP port (\feat{psfe_udp_active}).

\textbf{Group B: TCP options and payload (6 features).} From \feat{tcp.options} we take the byte length, whether the field begins with \texttt{0204} (maximum segment size option), and whether it contains \texttt{080a} (timestamp option). From \feat{tcp.payload} we take the byte length, the value of the first byte, and the Shannon entropy~\cite{shannon1948} of the first 64 hexadecimal characters,
\begin{equation}
H=-\sum_{k=1}^{16}\hat p_k\log_2\hat p_k,\qquad \hat p_k=\frac{n_k}{n},
\label{eq:entropy}
\end{equation}
where $n$ is the number of characters considered and $n_k$ the count of hexadecimal symbol $k$. Because the alphabet has 16 symbols, $H\in[0,4]$ bits per character; empty or single-character payloads score zero.

\textbf{Group C: application layer (9 features).} Before the URI, query, body and MQTT message columns are dropped, we record four lengths: the URI path length after the scheme and host are stripped, the query length, the HTTP body length (\feat{psfe_http_file_data_len}), and the MQTT message byte length. We add five binary lexical markers over the lower-cased URI, query and body, supplemented by short hexadecimal payload signatures: SQL injection tokens (\texttt{select}, \texttt{union}, \texttt{extractvalue}, \texttt{sleep}, \texttt{\%27}, and similar), script injection tokens (\texttt{script}, \texttt{alert}, \texttt{iframe}), upload tokens (\texttt{upload}, \texttt{multipart}, \texttt{hack.php}), authentication tokens (\texttt{login}, \texttt{password}, \texttt{user\_token}, \texttt{username}), and timeout or malformed-request status text.

\subsection{Pipeline and split}
Algorithm~\ref{alg:pipeline} gives the order of operations. Two choices matter. Deduplication happens before the split, so identical flows cannot straddle it. And the split happens before any encoder or scaler is fitted: categorical codes come from an ordinal encoder fitted on the training split with unseen categories mapped to $-1$, and a standard scaler is fitted on the training split only.

\begin{algorithm}[!t]
\caption{Leakage-controlled preprocessing and PP-PSFE}
\label{alg:pipeline}
\begin{algorithmic}[1]
\State Load $D_{\text{raw}}$ (157,800 rows)
\State $F \gets$ PP-PSFE features computed from the raw port, TCP, URI, query, body and MQTT columns
\State Drop the 15 identifier/raw columns, 8 constant fields, and the second label
\State Repair \feat{dns.qry.name.len}; apply $S(\cdot)$ of Eq.~\eqref{eq:canon} to categorical fields
\State $D \gets [D_{\text{core}} \,\|\, F]$; remove non-finite rows and duplicates (152,386 flows)
\State Stratified split of $D$ into $D_{\text{train}}$ (80\%) and $D_{\text{test}}$ (20\%), seed 42
\State Fit encoders and scaler on $D_{\text{train}}$ only; transform both splits
\State Fit each classifier on $D_{\text{train}}$; evaluate once on $D_{\text{test}}$
\end{algorithmic}
\end{algorithm}

The final representation has $d=62$ features: 32 numeric and 6 categorical core protocol fields, and the 24 PP-PSFE features.

\section{Results}\label{sec:results}
\subsection{Overall performance}
Table~\ref{tab:overall} and Fig.~\ref{fig:overall} report the four models on the held-out split. XGBoost has the highest test accuracy (96.49\%) and macro-F1 (0.9618). LightGBM is close behind at 96.33\% and 0.9596, and has the higher macro PR-AUC (0.9888 against 0.9874). The 0.16-point accuracy difference between the two is 49 flows out of 30,478. With one split and one seed we do not treat it as a ranking.

What separates them is cost and stability. XGBoost's train--test gap is 0.57 points against 2.10 for LightGBM, a factor of 3.7, and its inference time is 3.54~ms per 1,000 flows against 18.35~ms, a factor of 5.2 or roughly 282,000 flows per second on our machine. Random forest and logistic regression have the smallest gaps but give up 2.1 and 11.6 accuracy points respectively. The weakness of the linear model is not uniform, as the next subsection shows.

\subsection{Per-class behavior}
Table~\ref{tab:perclass} gives per-class scores. Eight classes are essentially solved by every tree model: \cls{Backdoor}, \cls{DDoS_TCP}, \cls{DDoS_UDP}, \cls{MITM}, \cls{Normal}, \cls{Port_Scanning}, \cls{Ransomware}, and \cls{DDoS_ICMP}. On the 4,831 benign test flows XGBoost has precision 0.9996 and recall 0.9998: one benign flow is flagged and two attack flows are labeled benign. \cls{DDoS_TCP}, \cls{Ransomware} and \cls{MITM} reach F1 of 1.0000.

The interesting classes are the five that face HTTP. On the same 62 features, logistic regression scores F1 between 0.44 and 0.66 on them (\cls{Password} 0.4371, \cls{SQL_injection} 0.5746, \cls{DDoS_HTTP} 0.6067, \cls{Uploading} 0.6354, \cls{XSS} 0.6585). XGBoost raises these to 0.8875, 0.9010, 0.8562, 0.9294 and 0.9285, gains of 45.0, 32.6, 25.0, 29.4 and 27.0 points. Fig.~\ref{fig:perclass} shows the contrast across all classes, and Fig.~\ref{fig:cm} shows where the remaining mistakes fall.

Those mistakes are concentrated. Of the 1,069 test errors made by XGBoost, 975 (91.2\%) are confusions between two of the five HTTP-facing classes, although these classes make up a third of the test set (10,122 of 30,478 flows). The largest single cells in Fig.~\ref{fig:cm} are \cls{SQL_injection} predicted as \cls{DDoS_HTTP} (203 flows), \cls{Uploading} predicted as \cls{XSS} (175), \cls{Password} predicted as \cls{DDoS_HTTP} (141), and \cls{Password} predicted as \cls{SQL_injection} (114). \cls{DDoS_HTTP} remains the weakest class by F1 (0.8562). We read this as the visible limit of header-level and length-level evidence: a flood of valid requests and a short injection attempt can have similar sizes and flags.

\section{Explaining the Model}\label{sec:xai}
We computed exact TreeSHAP attributions~\cite{lundberg2020} with XGBoost's native \texttt{pred\_contribs} on the first 2,000 held-out test flows ($N_{\text{SHAP}}=2{,}000$), and we also record the total loss reduction (gain) each feature earns across all trees. The 24 PP-PSFE features account for 73.88\% of total gain and 57.1\% of mean absolute SHAP magnitude, and they hold 12 of the top 20 SHAP positions (Fig.~\ref{fig:shap}). Table~\ref{tab:gain} lists the twelve features with the largest gain.

The two rankings disagree in a useful way. Gain is dominated by binary indicators that make clean early splits: the MQTT port indicator alone takes 24.00\% and the HTTP body length takes 19.20\%. SHAP, which measures how far a feature moves the prediction, puts \feat{psfe_service_port}, \feat{tcp.flags} and \feat{psfe_ephemeral_port} on top. Both views agree that the model leans mostly on the engineered features, and that the leaning is spread over many of them.

Attribution measures reliance and does not measure validity. Some of what the model relies on is protocol mechanics: TCP flag combinations separate scans and floods from ordinary sessions, and the body-length and injection-token features carry the information that distinguishes uploads and injections from floods. But the second- and third-ranked SHAP features involve the service and ephemeral port, and several core fields in the top 20 are counters or sequence values (\feat{udp.stream}, \feat{tcp.seq}, \feat{tcp.ack}, \feat{icmp.seq_le}). We return to this in Section~\ref{sec:limits}.

\section{Deployment}\label{sec:deploy}
Models that exist only in notebooks are hard to check and hard to reuse~\cite{sculley2015}, so we packaged the work. The fitted \texttt{ColumnTransformer}, with string-safe wrappers around six ordinal encoders for the categorical fields and passthrough for the 56 numeric inputs in fixed column order, the scaler, and the XGBoost classifier are saved as one scikit-learn~\cite{pedregosa2011} pipeline (\texttt{model\_bundle.joblib}). Keeping preprocessing and model in one object removes a common source of training--serving skew.

A Flask service exposes \texttt{GET /health} and \texttt{POST /predict}. An Angular~22 standalone interface calls it through a development proxy, offers one-click example flows (benign telemetry, \cls{DDoS_TCP}, \cls{SQL_injection}, \cls{Ransomware}), and shows the predicted class with the five most probable classes (Fig.~\ref{fig:ui}). Two GitHub Actions workflows run the backend \texttt{pytest} suite and the Angular production build, and publish the static interface to GitHub Pages. The live prediction endpoint runs locally; the Pages build disables prediction and says so.

The service takes the 62-dimensional feature vector as input. It does not yet extract PP-PSFE features from raw TShark output, so a client must compute them. Closing that gap is the most useful next engineering step. The interface is a research and teaching prototype, and predictions should be checked against other network telemetry before they drive automated blocking.

\section{Limitations and Threats to Validity}\label{sec:limits}
We list these in roughly the order a careful reviewer would raise them.

\textbf{Feature-group ablation and temporal sensitivity.} Table~\ref{tab:ablation} directly isolates the contribution of PP-PSFE and examines its temporal stability. Under random stratified splitting, adding the 24 PP-PSFE features to the 38 core fields boosts XGBoost accuracy from 88.97\% to 96.57\% (+7.60\%) and macro-F1 from 0.8900 to 0.9621 (+7.21\%), confirming that structural feature engineering accounts for the performance leap rather than model architecture alone. Removing Group~A port features degrades accuracy to 90.95\%, while removing only the raw continuous port values (\feat{psfe_service_port}, \feat{psfe_ephemeral_port}, \feat{psfe_port_span}) while retaining binary role flags preserves 92.64\% accuracy.

When evaluated under a temporal split (earliest 80\% of each class in training, latest 20\% in testing), a critical vulnerability emerges: full PP-PSFE ($d=62$) drops to 79.40\% accuracy (0.7638 macro-F1) because raw ephemeral client ports drift chronologically across attack sessions. Strikingly, when raw continuous port coordinates are stripped (\feat{core + PP-PSFE minus raw ports}, $d=59$), time-ordered accuracy rebounds to \textbf{91.70\%} (0.9151 macro-F1), outperforming the core-only baseline (87.93\%) by +3.77\% and demonstrating that discrete protocol-role flags and application-layer structural indicators generalize across time. Furthermore, removing capture-order sequence counters (\feat{udp.stream}, \feat{tcp.seq}, \feat{tcp.ack}, \feat{icmp.seq_le}) collapses time-ordered accuracy to 66.39\% (0.6037 macro-F1), verifying that flow counters carry substantial session-ordering leakage.

\textbf{The split is random.} Flows from the same capture session fall on both sides of the split. Deduplication removes identical rows, not near-identical neighbors from one session. Results from session-disjoint or capture-disjoint evaluation, or from a second dataset, are the standard that Kostas \emph{et al.}~\cite{kostas2025} and Roy~\cite{roy2026} argue for, and we have not run them. ``Leakage-controlled'' in this paper therefore means that the specific artifacts in Section~\ref{sec:audit} and the fitting-order errors are removed, and no more.

\textbf{Some PP-PSFE features can still encode the testbed.} Equations~\eqref{eq:service}--\eqref{eq:dir} keep the service port and the larger port, which for client traffic is an ephemeral port that attack tools and operating systems pick in characteristic ways. The port sets in Group A were chosen by inspecting this corpus, and some hexadecimal signatures in Group C match paths of the vulnerable web application used as a target in the testbed (for example the fragment \texttt{GET /DVWA/vulnerabil}). Those features are not portable to another network. Their presence among the top SHAP features (Fig.~\ref{fig:shap}) is a reason for caution about the 57.1\% figure as evidence of general protocol understanding.

\textbf{Retained core fields may also be identity-adjacent.} Fields such as \feat{udp.stream}, \feat{tcp.seq}, \feat{tcp.ack} and \feat{icmp.seq_le} depend on capture order or sender stack. We kept them because they are standard header fields, but a stricter protocol would test their removal.

\textbf{Statistical evidence is thin.} Each model is trained once on one split with one seed, without confidence intervals. The XGBoost--LightGBM accuracy difference is within what we would expect from seed variation. Hyperparameters were not tuned, which may disadvantage the models differently.

\textbf{Smaller points.} Payload entropy is computed over hexadecimal characters of at most the first 64, rather than over decoded bytes. The TreeSHAP shares are computed on the first 2,000 test flows ($N_{\text{SHAP}}=2{,}000$) and depend on the sample. Timings come from one CPU machine. The deployed service does not extract features from raw captures.

\section{Conclusion}\label{sec:conclusion}
Edge-IIoTset's ML release contains a serialization artifact that makes file provenance readable as a class label, an export fault that corrupts a numeric column, constant columns, and thousands of duplicate rows. Removing them, together with the columns that identify the laboratory, is necessary and costly: it discards most of what separates web attacks. Extracting 24 structural summaries before the removal gave a 62-feature representation on which XGBoost reached 96.49\% accuracy and 0.9618 macro-F1 on 152,386 deduplicated flows, with most remaining errors confined to confusions among five HTTP-facing classes.

We would not call these numbers a generalization result. They come from a random split, a single seed, and features that may still carry some testbed regularities. The next experiments are a feature-group ablation, a session-disjoint or time-ordered evaluation, and a test on a second dataset; if PP-PSFE helps there, the argument for it becomes much stronger. Until then the audit procedure, the explicit feature definitions, and the packaged pipeline are the parts of this work that others can reuse directly.
